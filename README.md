# 健身打卡助手（Fitness Check-in Assistant）

一个**单文件、零依赖、纯本地**的健身打卡 Web 应用：把每天的运动、饮食、饮水、睡眠和身体数据放在一个页面里，帮助健身人群用最低的操作成本完成记录，并看到趋势。

- 源码：`index.html`（HTML + CSS + 原生 JavaScript，无构建、无后端）
- 数据：浏览器 `localStorage`，不上传服务器
- 适用：桌面 Chrome / Edge，手机浏览器（390px 宽度已验证）

## 项目用途

健身记录通常散落在备忘录、聊天记录和多个 App 中：喝了多少水、今天练了什么、吃了多少、昨晚睡够没有，很难在同一个地方回看。这个项目把「记录 → 评估 → 看趋势」压缩到一页：

- 专业健身人群：按克数精确记录饮食，关注蛋白质和运动消耗。
- 普通运动爱好者：按份数快速估算，降低记录门槛。
- 两类人群的数据完全分开，切换人群不会串数据。

## 主要功能

### 1. 本地账号与人群模式

- 手机号 + 密码登录、短信验证码登录（演示码直接显示在页面上）、注册、重置密码。
- 「专业健身人群 / 普通运动爱好者」两套模式，饮食录入方式和每日数据独立保存。
- 数据按账号隔离，同一浏览器可切换账号。

### 2. 每日打卡总览

- 饮水、运动、饮食三类目标完成度圆环，达标后可完成当日打卡。
- 连续打卡天数、今日总消耗（基础代谢 + 运动净消耗）。

### 3. 饮水 / 运动 / 饮食记录

- 饮水：+250ml、+500ml、自定义、撤销，目标 2000ml。
- 运动：20 个常见项目快捷选择，也支持自定义；按 MET 估算消耗，逐项勾选完成。
- 饮食：内置常见食物热量/蛋白质库；专业模式按克数，普通模式按份数；超出目标会提示。

### 4. 睡眠记录

- 录入入睡时间、起床时间、半夜清醒时长，自动处理跨午夜。
- 自动计算实际睡眠时长、约几个 90 分钟睡眠周期，给出「良好 / 睡眠不足」评价。
- 睡眠不足时提示「睡眠偏少，高强度运动容易头晕乏力」，当天有高强度运动时给出降强度建议；睡眠充足时触发月亮表扬动画。

### 5. 个人档案与身体数据台账

- 点击顶部带手机号的个人入口，查看身高、体重、年龄、性别。
- 一键计算 BMI，给出偏瘦 / 健康 / 超重 / 肥胖评价与简单建议，并结合最近腰围提示腹型肥胖风险。
- 身体数据台账记录体重、腰围，每次录入自动生成体重变化折线图，可删除记录。

### 6. 运动数据可视化与导出

- 「本周 / 本月（按周汇总）」运动总时长柱状图。
- 体重变化折线图（读取身体数据台账）。
- 导出打卡记录为 `.txt`：包含两种人群的饮水、运动、饮食、睡眠、打卡状态和身体数据台账；手机端调起分享面板，电脑端直接下载。

### 7. 历史与外观

- 近 7 天记录、近 3 个月历史明细。
- 5 套皮肤（粉色 / 黑白 / 绿色 / 蓝色 / 赛博）+ 夜间模式；夜间模式下皮肤名称使用对应亮色。

## 技术栈与项目结构

- HTML5 + CSS3（CSS 变量实现 5 套皮肤和夜间模式）
- 原生 JavaScript（ES5 写法，无框架、无构建工具）
- 浏览器 `localStorage` 持久化
- 图表为手写 SVG，导出使用 `Blob` + `download` / Web Share API

## 本地启动步骤

### 方式一：直接打开（最快）

1. 下载或克隆仓库。
2. 双击 `index.html`，用 Chrome 或 Edge 打开。
3. 用演示手机号注册 / 登录后即可使用。

> 个别浏览器会限制 `file://` 下的 `localStorage`，若遇到数据不保存，改用方式二。

### 方式二：本地静态服务器（推荐）

项目没有任何依赖，装好 Python 3 即可：

```bash
cd fitness-checkin
python -m http.server 8000
```

然后打开 <http://localhost:8000>。

也可以用 VS Code 的 Live Server 插件，或 `npx serve .`。不需要 `npm install`，不需要数据库和后端。

## 手机 / iPad 访问

iOS / iPadOS 不允许从「文件」App 直接双击运行本地 HTML（通常只显示静态预览，脚本和本地存储受限），所以手机/iPad 请通过**网址**访问：

- 推荐：部署到 GitHub Pages 等静态托管，用 `https://...` 打开；
- 临时：在电脑上启动本地服务器（见上方方式二），手机/iPad 与电脑连同一个 Wi-Fi，访问 `http://电脑局域网IP:8000`。

页面已做移动端兼容：`localStorage` 不可用时自动降级为内存存储；旧版 Safari 补充了 `padStart`、`NodeList.forEach`、`closest`、`Array.find` 的 polyfill；弹层使用 `top/right/bottom/left` 作为 `inset` 的回退。直接打开本地文件时若无法保存，页面会给出提示。

## 已知问题

1. **纯本地存储**：换设备、换浏览器、清理浏览器数据都会丢失记录，没有云端同步和备份；导出的 `.txt` 只能阅读，暂不支持重新导入。
2. **账号体系是演示级**：手机号、密码、验证码都在前端处理，密码以明文存在 `localStorage`，没有服务端校验，不能用于生产环境。
3. **BMI 与睡眠是估算**：BMI 只反映体重与身高的关系，不等于体脂率；睡眠周期按 90 分钟粗略估算，评价和建议仅供参考，不构成医疗建议。
4. **导出格式限制**：手机端通过系统分享面板保存 `.txt`，无法直接存进系统相册（相册主要接收图片/视频）；电脑端会下载到默认下载目录。
5. **图表范围有限**：只支持本周 / 本月，且运动数据按当前人群类型统计；暂不支持自定义日期区间和多种运动类型对比。
6. **未做完整兼容性测试**：主要在桌面 Chrome / Edge 和 390px 宽度下验证；Safari、部分国产浏览器和超小屏设备未逐一测试。
7. **无自动化测试**：目前依赖手动验收清单（见 `AGENTS.md`），后续可补 Playwright 冒烟测试。
8. **隐私提醒**：`localStorage` 未加密，共用电脑上其他使用者可以看到记录，建议演示后清理数据。
